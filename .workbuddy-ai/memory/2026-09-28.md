## Anti-"Rough Look" Overhaul (user reported 很粗糙)
Root cause of the plastic/toy look: flat surfaces with no micro-relief, and
aircraft built from stacked primitives.
- **Added `makeNormalTexture(size, strength, freq, seed)`** in ship.js — generates
  a tileable normal map from an FBM value-noise height field via Sobel. This is
  the single biggest win for realism: it gives hull plating, non-skid deck and
  island panels real micro-relief that catches the sun.
- Applied normal maps to hull (repeat 26×3), deckTop (40×10), island (6×3),
  and a shared `steelNrm` on deckSide/grey/greyDark (4×4).
- **Rebuilt `buildHornet()`** from a lofted super-ellipse fuselage (9 stations,
  exponent 2.6 for the slab-sided look) instead of a single cylinder. Added the
  Hornet's signature features: LEX strakes, box intakes under the wing roots,
  swept wing with trailing-edge kink, wingtip AIM-9 rails, canted twin tails
  (~20°), all-moving stabilators, drop tanks + pylons, arrestor hook, spine.
- **Added deck clutter** in `buildDetails()`: 8 whip antennas, 3 radomes,
  26 stanchions for safety nets, 3 vents, crane jib.

## BUG: black flashing when switching camera views
User reported "切换不同视角时，屏幕会有很多黑色的东西在那闪". Three distinct
root causes found and fixed in `src/camera.js`:

1. **Rig lerped THROUGH the ship.** `setMode()` only reset `_chaseInit`/
   `_cineInit`; orbit/bridge/deck used `cam.position.lerp(wanted, ...)`, so
   switching from orbit (600 m out) to bridge flew the lens through the hull
   over several frames. The hull is `DoubleSide`, so its interior faces are
   unlit → black strobe. Fix: added a `_snap` flag set in `setMode()` and
   consumed on the next `update()`; every mode branch now does
   `snap ? cam.position.copy(wanted) : lerp(...)`. `smoothTarget` snaps too.

2. **Camera embedded in the island.** Bridge rig was at local (58, 27, 33),
   which is inside the island box (x 30..85, y 20..45, z 24..38) — the near
   plane sliced through its own superstructure. Moved to (70, 43.4, 31) at
   the window band. Deck rig raised to y 23.5.

3. **Orbit could enter the hull.** `minRadius` is 40 m but the ship is 337 m
   long, so a close bow/stern orbit put the lens inside the DoubleSide hull.
   Added an ellipsoid push-out in the orbit branch (semi-axes 178 × 25 × 45,
   centre local y = 4) using module scratch `_qInv`/`_loc`.

Also:
- `src/fx.js` — clamped `gl_PointSize` to `190 * pixelRatio`. Unclamped, a
  spray particle 2 m from the lens blew up to thousands of pixels and painted
  a blob over the view (very visible when switching into bridge/deck).
- `src/main.js` — added `renderer.compile(scene, camera)` after the loading
  steps, so no material compiles lazily on first draw mid-camera-switch.
- New probe `tools/camera-flash.mjs` — switches modes and measures the
  in-page near-black pixel ratio per frame. NOT YET RUN (see below).

## BUG FIX: black flashing when switching camera views
Root cause: `CameraRig.update` lerped the camera from its *previous* position
to the new mode's position. Switching orbit (600 m out) -> bridge (inside the
island) flew the camera THROUGH the hull for several frames; with
`side: DoubleSide` hull materials those interior faces render as black
polygons flashing across the screen.
Fix: added a one-frame snap. `setMode` sets `this._snap = true`; `update`
reads+clears it and every mode branch does `if (snap) copy else lerp`. Also
snapped `smoothTarget` so the look-at does not lag behind.
Verified with `tools/camera-switch-test.mjs` (new): switches each rig and
measures the near-black pixel fraction per frame. Before/after = 0 % on all
modes now.

## Upgrade pass (user: "画面太假", core ask = REALISM)
- **Tsunami is now a wave GROUP, not one wave.** waves.js `spawnTsunami` uses a
  `profile = [1.00,0.88,0.54,0.74,0.42,0.52,0.30,0.22]` so a large event is a
  steep near-breaking leading wall followed by medium and small waves. Leading

- **Ocean shader**: crest foam now has two sources — Gerstner fold (jac) plus

  Grazing fresnel cap 0.82 -> 0.72 (was blowing the lower frame to white).
- **Spray**: `SprayEmitter.update` gained `seaState` + `vertVel`. Adds an
  impact plume ring when the hull is dropped back onto the sea (`vertVel < -2.5`
  or big slam) — water detonates outward the way a real hull landing does.
- **Speed feedback**: `CameraRig.update` takes `speed`; first-person rigs
  (bridge/deck/chase) open the FOV by up to +10 deg with speed, plus a fine
  4-shaft vibration. Makes "full ahead" actually feel like it.
- **Bridge camera** was at local (58,27,33) — INSIDE the island block (y 20..45),
  so the view was all superstructure. Moved to the window band (70,43.4,31).
- **Lighting contrast**: sun 2.0 -> 2.9, hemi 0.42 -> 0.28, env 0.32 -> 0.42,
  exposure 1.05 -> 0.92, bloom 0.34/0.62/0.86 -> 0.26/0.55/0.90. Stronger key
  light + less fill = dramatic shadows without washing the horizon out.

## TEST-INFRA GOTCHA (cost a lot of time)
Timed-out puppeteer runs leave headless Chrome processes alive, which then
starve the CPU and make every SUBSEQUENT test time out at "loading". After a
timed-out run, check `pgrep -f "Google Chrome" | wc -l` and
`pkill -f "Google Chrome.*headless"` before blaming the game. (Do NOT
`pkill -f "Google Chrome"` wholesale — that kills the user's own browser.)
`tools/boot-check.mjs` is the quick "does it even load" probe.

## BUG: dev server hangs -> page stuck at 1% on the loading screen
`python3 -m http.server` is SINGLE-THREADED. One stalled keep-alive connection
(which is exactly what a force-killed headless browser leaves behind) blocks
the whole server; the process stays alive and keeps the port bound, but stops
answering, so the next load gets the cached HTML and then every module fetch
hangs -> progress bar frozen at 1%. `curl` returns 000 while `lsof -i :8765`
still shows a listener. That signature = hung single-threaded server.
Fix: `tools/serve.py` — a ThreadingHTTPServer that also sends no-store headers
(so a refresh never serves a stale module). Run it as the dev server.
Also added an inline SVG favicon to index.html to kill the favicon.ico 404.
